# 粤语语种识别调用排查报告

测试日期：2026-10-26。输入为 `model/标准语音测试集/yue-cantonese.wav`，16.45 秒。仅代表这条样本。

## 调用核对

- 自动模式实际传入 `-l auto`；JSON 的 params.language 为 auto，result.language 为 zh。原生日志也记录 auto-detected language: zh，并非报告层把 yue 映射成 zh。
- Orbination 日志为 n_vocab=51866、n_langs=100。当前原生检测遍历语言候选，包含 yue；最大概率仍属于 zh。
- Java 方法先调用 whisper_pcm_to_mel，再调用 whisper_lang_auto_detect，没有将 yue 转成 zh。本次绕过 Java、直接用 CLI，也复现了该现象。
- Tiny／Base 没有独立 yue token；不能根据本地库能查询 yue 名称就认定具体模型支持该分类。

## 同音频强制 yue 对照

在自动化测试结束后，三个 Orbination 模型分别增加 `-l yue`，其余保持 8 线程、Beam Search 5、关闭 Flash Attention、不继承上下文。每模型执行一次诊断转写，不作为三轮性能比较。强制模式输出 language=yue 是调用方指定的，不表示自动语种识别成功。

| 模型 | 自动检测结果 | auto 文本 CER | 指定 yue 文本 CER |
|---|---|---:|---:|
| Q3_K | zh | 38.30% | 78.72% |
| Q4_K | zh | 38.30% | 71.28% |
| Q5_K | zh | 37.23% | 77.66% |

CER 使用相同参考稿及字符规范化规则，包含简繁字形差异。强制 yue 后不仅分数变差，还缺失了大量后半段内容，不能认为改参数就解决了问题。

原始强制输出和日志保存在 `测试结果/粤语指定语种对照/`。自动模式完整转写见[五模型报告](标准语音五模型测试报告.md)。

## 结论与边界

本次调用路径未发现设置错误。模型在这条粤语音频上选择 zh；强制 yue 后文本更差。仅凭本例还无法区分原版 Turbo 能力、Orbination 微调／量化影响或样本特性，需要原版未量化 Turbo 和更多标注粤语音频才能继续归因。

不要将 zh 无条件改成 yue，否则普通话也会被错误分类；语种分类和粤语文本质量应分开评测。

Whisper 项目里也有使用者报告 Large-v3／Turbo 将粤语识别成 zh：[讨论 #2419](https://github.com/openai/whisper/discussions/2419)。这是相似现象的使用者报告，不是维护者确认的根因或修复承诺。
